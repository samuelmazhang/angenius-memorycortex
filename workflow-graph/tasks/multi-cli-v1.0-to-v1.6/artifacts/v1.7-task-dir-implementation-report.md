## 2. 标准目录结构

```
workflow-graph/tasks/                   # 主 hermes 中心 task 中控副本
├── README.md                           # 目录说明(只创建一次)
├── index.jsonl                         # 所有 task 的索引(主 hermes 启动读这个)
└── {task-name}/                        # 每次任务一个独立目录
    ├── dispatch-prompt.md              # 主 hermes → 子代理的原始 prompt 原文
    ├── spec.md                         # task spec / metadata
    ├── subagent-report.md              # 子代理返回的 report
    ├── reviewer-verdict.md             # reviewer verdict
    ├── decision-log.md                 # 主 hermes 关键决策记录
    ├── progress.json                   # 心跳进度(从 worktree .sprint/ 复制)
    ├── audit.jsonl                     # 统一 audit log(从 worktree .sprint/audit/ 合并)
    └── artifacts/                      # 子代理产物 (diff / screenshot / test output)
```

## 3. 关键设计决策

### 3.1 task-name 格式

- kebab-case + 允许 `.` / `#`
- 例:`multi-cli-v1.0-to-v1.6` / `cortex-recall-fix-#2.1` / `sprint-validation-2`
- 不允许空格 / 中文 / 特殊符号

### 3.2 .gitignore 例外

```
workflow-graph/*                  # graph.db 等本地状态不入仓
!workflow-graph/tasks/            # 但 tasks/ 子目录入仓
!workflow-graph/tasks/**          # tasks/ 下所有文件入仓
```

效果:`graph.db` 不入仓(本地状态),`tasks/` 入仓(审计 trail)。

### 3.3 跟 worktree 互补

| 位置 | 内容 | 何时写 |
|---|---|---|
| **worktree `.sprint/`** | 实时数据(progress / audit / base) | 子代理每 30 秒写 |
| **workflow-graph/tasks/{name}/** | 中控副本(snapshot) | dispatch 后 / task 完成后 |
| **workflow-graph/tasks/index.jsonl** | 全局索引 | 每次 create/register 追加 |

### 3.4 主 hermes 启动 workflow

```
主 hermes 启动
   ↓
读 workflow-graph/tasks/index.jsonl
   ↓
看到 [task-name, created_at, scenario, cli, status] 列表
   ↓
要看某个 task:cd workflow-graph/tasks/{task-name}/
```

任何时候复盘,**5 秒定位 task 全部产物**。
