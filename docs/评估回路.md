# 召回效果评估回路

> **来源**: V2.0 引入（Post-LLM 自评），V4.2 加 LLM-as-Judge
> **核心模块**: `src/hooks/02_memory_evaluation.py`
> **核心创新**: 端到端评估回路（开源 RAG 罕见）

---

## 一、为什么需要评估回路

`relevance_score` 仅靠 `access_count` 驱动遗忘曲线有缺陷：
- 旧记忆可能 `access_count` 高但实际从未被 LLM 使用
- 关联召回 ≠ relevance_score 升高
- 注入记忆是否真正帮助 LLM，无自动验证

**解决思路**: 在 `pre_llm_call` 注入之后，新增 `post_llm_call` 评估钩子，形成**自评回路**：

```
用户提问 → 注入记忆 → LLM 生成 → post-LLM 评估 → 更新 relevance_score
                                                        ↓
                                              遗忘曲线基于真实效果淘汰
```

---

## 二、评估指标（V2.0 regex 三维度）

| 维度 | 权重 | 计算 |
|------|------|------|
| 术语精确重叠 | 50% | 记忆中的技术术语（驼峰/路径/版本号/D-ID）在 LLM 响应中出现 |
| 意图满足 | 25% | 用户问题关键词在记忆中出现 |
| 内容引用 | 25% | 记忆内容关键词在 LLM 响应中复述 |

**术语提取规则** (`_extract_terms`):
- 驼峰/下划线: `Regex(r'\b[a-z][a-z0-9_]{2,}[A-Z]\w*')`
- 路径片段: `re.findall(r'(?:/[\w.-]+){1,}')`
- 文件名: `*.py / *.sh / *.md / *.yaml / *.cs`
- 版本号: `v3.19 / v3.50.0`
- 决策 ID: `D3.22-1 / D3.16-1`
- 中文: 连续 3+ 字符
- 命令关键字: `grep / find / cd / patch / curl`

## 三、V4.2 LLM-as-Judge（灰色区间二次评估）

### 3.1 触发条件

`relevance_score ∈ [0.3, 0.7]` 时，正则不确定 → 调 LLM 二次评估。

### 3.2 综合算法

```
final_score = 0.6 × llm_score + 0.4 × regex_score
```

LLM 占主导（60%），正则兜底（40%）。

### 3.3 评估 Prompt

```python
# src/hooks/02_memory_evaluation.py
judge_prompt = f"""判断这条记忆对回答用户问题有多大帮助：
- 记忆内容: {memory_content}
- 用户问题: {user_query}
- LLM 回答: {llm_response}
只输出 0-1 之间的数字 (1 位小数):
- 0.0-0.3: 完全无关
- 0.4-0.7: 边缘相关
- 0.8-1.0: 核心信息
"""
```

### 3.4 配置（默认关闭）

```bash
LLM_LLM_JUDGE_ENABLED=true          # 默认 false
LLM_LLM_JUDGE_URL=http://localhost:8080/v1
LLM_LLM_JUDGE_MODEL=MiniMax2-M3
```

## 四、relevance_score 更新策略

```python
# 基础召回分
base_score = 0.1
# 评估增量: 高于阈值才加分
relevance_increment = max(0.0, evaluation_score - 0.1)
# 评分范围
score ∈ [0.0, 1.0]
```

`judge_method` 标记:
- `"regex"` — 仅正则
- `"llm_judge"` — LLM 二次评估（v4.2+）

## 五、API 端点

### 5.1 `POST /eval/feedback`

**请求**:
```json
{
  "feedback": [
    {
      "memory_id": "mem_xxx",
      "relevance_increment": 0.15,
      "evaluation_score": 0.25,
      "user_query": "QuantPlatform v3.20 P0 拍板",
      "judge_method": "regex"  // 或 "llm_judge" (v4.2)
    }
  ]
}
```

**响应**:
```json
{ "updated": 1, "total": 1 }
```

## 八、已知局限

1. **术语提取依赖正则**: 无法识别项目特有术语的自创模式（如 `StrategyBuilderPhasePanel`）
2. **评分启发式**: 当前正则 + LLM 混合，未做 fine-tune
3. **未批量评估**: 每次响应后单独评估
