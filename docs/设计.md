# Memory Cortex V6.0 当前实现设计

> 本文描述当前 PostgreSQL + pgvector 运行路径。V4 的 SQLite/Chroma 设计已归档，不再作为实现规范。
> **V6.0 (2026-08-06)**: ADR-067 全部 P0+P1+P2 合入 + ADR-068 冲突解决 + ADR-069 数据治理 + ADR-070 cron 告警 + ADR-071 死代码清理 + ADR-072 WebUI E2E.

## 1. 存储

记忆主体存储在 PostgreSQL `memory_chunks` 表中，向量字段使用 pgvector，当前 Embedding 维度为 384。数据库初始化和索引定义位于 `server/docker/unified/schema.sql`。

## 2. 混合检索

`POST /search` 执行三路召回：

- pgvector 向量相似度
- PostgreSQL lexical / ts_rank
- 标签召回

随后使用 Reciprocal Rank Fusion 和 importance、recency、relevance 等信号重排。需要图谱上下文时传 `include_related=true`。

## 3. 图谱推理

`POST /graph/mine` 对历史记忆进行幂等关系挖掘；`GET /graph/khop` 负责从种子记忆执行有界 BFS。Hermes Connector 的 `reason_with_memory` 将搜索命中、图谱节点、层级和链接合并为上下文。

## 4. 生命周期

系统通过 importance 派生 tier 和过期时间，并由 guided forgetting、cleanup、reconsolidate、rumination 和 storage eviction 共同治理记忆生命周期。永久记忆必须保持不可被普通 TTL 清理和低价值淘汰删除。

**Taxonomy boost (V6.0+ ADR-067 M8)**: chunk.tag 命中 `tags_taxonomy` 任何祖先层级 ∩ query.tag → composite_score × 1.2。Feature flag `MEMORY_FEATURE_TAXONOMY_BOOST` 默认 false。实现见 `server/src/memory_taxonomy.py`。

## 5. 集成

生产 Hermes 路径是 `connector/hermes/cortex_memory_backend.py`。formal provider 位于 `plugin_package/memory_cortex`，通过 `MEMORY_CORTEX_URL` 访问远端服务。takeover 和 provider 不得同时承担独立写入，避免重复记忆。

## 6. 规范

修改服务端行为时必须同步：

1. `server/src/api_pg.py`
2. OpenAPI baseline
3. Connector contract tests
4. 当前架构文档
5. CHANGELOG / VERSION

验证必须包含本地语法检查、连接器黑盒测试、远端 endpoint smoke test 和必要的真实数据行为验证。
