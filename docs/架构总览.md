# Memory Cortex 当前架构总览（V6.7.0）

> 本文是当前运行基线（版本以根 `VERSION` 与 `/health` 为准）。V4/V3 的 SQLite、Chroma 和旧 `src/*.py` 设计仅保留在历史文档中，不代表当前生产实现。
> 线上实测（2026-11-25）：`/health` 返回 `version=6.7.0, chunks=10241, relations=25274, vectors=10241`。

## 1. 系统定位

Memory Cortex 是面向 Hermes 和其他 Agent 的长期语义记忆服务，提供：

- 记忆片段 CRUD
- PostgreSQL + pgvector 向量存储
- 三路 RRF 混合检索
- 图谱关系与 k-hop GraphRAG
- 记忆重要性、热度、遗忘和存储淘汰
- Working Memory、Procedural Memory、Hierarchy
- Audit、History、Provenance
- Media、Resources 和 Dashboard

## 3. 数据与模型

| 项目 | 当前实现 |

| 主数据库 | PostgreSQL 16（容器内 PG + python 同镜像） |
| 向量扩展 | pgvector，HNSW 余弦索引（m=24, ef_construction=200）+ GIN tsvector |
| 向量维度 | `vector(768)`；mpnet 384 维零填充，nomic-v1.5 原生 768 维 |

| 当前版本 | 6.7.0 |
| API 路径 | 118 个 REST 路由（`/endpoints` 目录仅列 89 条，已陈旧）+ 104 MCP 工具 |

## 4. 检索架构

`POST /search` 是当前主检索入口（管线顺序按代码）：

1. **前置**：按 `model_version` 对齐查询向量与块向量空间；`hybrid=False` 走纯向量降级 `_search_vector_only`。
2. **多路召回**：向量（pgvector cosine / HNSW，top_vector 默认 24）+ 字面（`ts_rank` + GIN，权重 0.25）+ tag（JSONB 硬过滤）+ 可选 RAPTOR 摘要树（`walk(beam=3)`，命中直接追加进候选池）。
3. **RRF 融合**（`_rrf_fusion`）：通道权重 vector 1.0 / lexical 0.25 / tag 1.0 / raptor 0.5。
4. **Cross-Encoder 精排**（v6.6.0，可选）：请求 `rerank=true` 且 `MEMORY_FEATURE_RERANK=1` 双闸门；bge-reranker-base ONNX（量化优先），fail-open；结果作为 `ce_score` 注入最终打分（**不重排 candidates**，因为随后 `results.sort(key=composite_score)` 会盖掉）。
5. **图谱信号**：`include_related` → PPR 邻居扩展（`graph/ppr.py`，HippoRAG2 风格）或 legacy 过滤扩展；另有连通性打分 `_graph_signal()`。
6. **最终打分** `_three_factor()`：`0.5*rrf_norm + 0.4*sim_eff + 0.15*imp + 0.1*recency + 0.05*rlv + 0.30*ce + raptor_term + graph_term`（未归一化，可 >1）；taxonomy boost ×1.2（可配置）。
7. **回写副作用**：命中写 `access_stats`（热度）与 `memory_access_audit(action='search')`。

`GET /search/hybrid` 和 `GET /search/tts` 为兼容入口，二者都真实转发到 `search_memory()`，但只接受 `q`/`limit`（丢失 rerank/tag/model 等高级参数）；复杂检索请用 `POST /search`。

## 5. 图谱与推理

- `POST /graph/mine`：对存量记忆按相似度、共享标签、同来源挖掘关系（默认阈值 0.72，asyncio.Lock + to_thread）。
- `GET /graph/khop`：从指定记忆沿关系进行有界 k-hop BFS。
- PPR（Personalized PageRank）：`server/src/graph/ppr.py`，HippoRAG2 风格，结果缓存于 `memory_graph_ppr` 表；社区发现 `graph/community.py`（Leiden/Louvain/label-propagation），缓存于 `memory_graph_communities`。
- Connector 的 `reason_with_memory(..., khop=2)` 将搜索结果、层级、链接和图谱子图合并为上下文。
- RAPTOR 摘要树：`server/src/consolidate/raptor*.py`，索引持久化于 `memory_raptor_trees/nodes`，供检索作为额外召回通道。
- Spreading Activation（v7）仅在 `experiments/v7-spreading-activation/` 做 POC（ADR-073/074），**未进生产路径**。

## 6. 生命周期

当前服务支持：

- `importance` 驱动 tier 和 TTL（≤3 short/7d，≤5 medium/30d，≤7 long/180d，其余永久）
- **origin 绑定**（v6.6.0）：写入时记录 `origin/origin_trust/origin_ref`，信任等级 user > external > derived；`user|external` 强制 `origin_ref`
- **近重复抑制**（v6.6.1）：写入后立即对同 source、cosine≥0.93 的近重复旧块置 `is_deprecated` + `superseded_by`
- **冲突解决**（ADR-068）：写入后经 `ConsolidationScheduler` 异步做 SUPERSEDE/DEDUPE/KEEP，结果写 `memory_conflict_log`
- **维护调度器**：flush + worker 线程，任务表 `memory_maintenance_queue`，`SKIP LOCKED + lease(30s) + worker_id` 支持多 worker；LLM 抽取不可达时跳过（TCP 探测）
- **外部 cron**：`ops/maint/cortex_maint_{daily,weekly}.py`（默认 03:00/02:00，weekly 默认 dry-run）
- `forgetting/guided`：基于访问统计提升重要性；`forgetting/cleanup`：清理过期非归档记忆
- `storage/evict`：按存储预算淘汰低价值记忆
- `reconsolidate`：关系强度和记忆热度治理；`rumination`：矛盾检测、碎片合并和经验抽象
- heat 衰减：`/links/decay` 手动触发；服务内无独立 heat 衰减定时器

重要性 8–10 的永久记忆不得被普通 TTL 清理或存储淘汰删除。

## 7. Hermes 集成约束

每个 Hermes 进程必须只有一个 Cortex 写入所有者：

- takeover 模式由内置 memory tool 写入；或者
- formal provider 模式由 `memory-cortex` provider 写入。

不得同时启用两个独立镜像写入路径。Provider 的 `on_memory_write` 已设计为非写入钩子，以避免迁移期重复 chunk。
